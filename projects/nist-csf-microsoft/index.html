NIST Cybersecurity Framework 2.0 Implementation – Microsoft Environment

Designed and implemented a cybersecurity framework based on NIST CSF 2.0 for a Microsoft-based enterprise environment. The project maps governance, risk management, identity protection, endpoint security, threat detection, incident response and recovery activities to relevant Microsoft security capabilities.

01

Overview

NIST CSF 2.0, published in February 2024, is a voluntary framework that describes cybersecurity outcomes and leaves the choice of how to reach them to each organization. Organizations use it because it gives leadership and engineers one structure for discussing risk: where are we now, where do we need to be, and what comes first? Many companies already run on Microsoft 365 and Azure, so the practical question is which existing capabilities can support which outcome, and where policies and people have to do the rest. Tools alone do not achieve a CSF outcome.

What is on this page

My work
I mapped CSF 2.0 across its six functions, developed the risk register, asset inventory, current and target profiles and gap analysis, and implemented security controls using Microsoft Entra ID, Intune, Defender and Sentinel. I designed identity and access controls, developed vulnerability, monitoring, incident response and recovery procedures, and created the control register, roadmap, evidence repository and KPI dashboard.
Conceptual
The architecture and roadmap are simplified summaries. They leave out configuration details, and the product mapping is my own, not an official NIST or Microsoft mapping.
Illustrative
The risk register uses fictional data. Gap values are examples, not assessment results.

05

Gap assessment

A CSF Profile compares where an organization is with where it needs to be. The biggest gap is not always the first job: priority comes from the gap combined with business risk.
